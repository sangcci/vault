# Question: 화면에서 보여준 인원 수와 실제 신청 시점의 불일치는 어떻게 처리해야 할까

## 핵심 질문

> 사용자가 모집 인원을 보는 시점과 모집 신청을 클릭한 시점 사이에 마감되었을 때 어떡함?

---

## 왜 중요한가

목록 화면의 잔여 인원은 조회 시점의 값이라 오래될 수 있다. 이 값을 완전히 최신으로 유지하려고 모든 조회에 강한 lock을 걸면 읽기 성능과 사용자 경험이 나빠진다.

```text
목록 화면 조회 시점: 잔여 3명
        ↓ 5초 경과
다른 사용자 3명이 먼저 신청 완료
        ↓
현재 사용자 신청 클릭
        ↓
신청 API에서 DB 기준 최종 검증
        ↓
rowCount = 0 → 방금 마감됨 응답
```

따라서 화면 조회는 stale read를 허용하고, 실제 상태 변경 시점에 원자적으로 검증하는 구조가 필요하다.
