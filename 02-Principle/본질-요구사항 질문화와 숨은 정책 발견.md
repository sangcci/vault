# Principle: 요구사항 질문화와 숨은 정책 발견

**핵심 질문**: 화면에 보이지 않는 정책을 개발 가능한 조건으로 바꿨는가?

## 한 문장 정의

요구사항 질문화와 숨은 정책 발견은 UI나 기능 설명에 드러난 요소를 정렬, 중복, 권한, 상태, 예외, 변경 가능성 질문으로 바꿔 구현 전에 정책 공백을 찾는 원리.

---

## 판단 기준

```text
화면 요소
  ↓ 질문화
정렬 기준 / 노출 개수 / 중복 가능성
권한 / 예외 상태 / 페이지 방식
상태 전이 / 변경 빈도 / 운영 정책
  ↓
API / DB / Front 상태 / 테스트 조건
```

---

## 실무 기준

- 화면에 보이는 필드보다 보이지 않는 정책을 먼저 질문한다.
- 질문은 공격이 아니라 개발 가능한 조건으로 번역하는 과정이다.
- 미결정 정책은 명시적으로 기록한다.
- 프론트/백엔드 파트가 나뉘어도 요구사항 흐름은 하나로 본다.
- 변경 가능성이 큰 정책은 API 경계와 DB 모델에 반영한다.
