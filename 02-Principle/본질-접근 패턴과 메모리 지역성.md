# Principle: 접근 패턴과 메모리 지역성

**핵심 질문**: 같은 O(n) 순회라도 왜 배열 기반 구조가 노드 기반 구조보다 빠를 수 있는가?

## 한 문장 정의

접근 패턴과 메모리 지역성은 자료구조의 시간복잡도뿐 아니라 데이터가 메모리에 어떻게 배치되고 CPU가 어떤 순서로 접근하는지가 실제 성능을 좌우한다는 원리.

---

## 해결하는 문제

- `ArrayList`와 `LinkedList` 선택을 Big-O 표만 보고 결정하는 문제
- 순차 조회가 많은데 노드 기반 구조를 선택해 cache miss가 늘어나는 문제
- 중간 삽입/삭제 O(1)만 보고 위치 탐색 비용을 빼먹는 문제
- 인터페이스가 같으면 구현 비용도 같다고 착각하는 문제

---

## 판단 기준

```text
ArrayList
  - 연속 배열
  - index 접근 O(1)
  - 순차 접근 locality 좋음
  - 중간 삽입/삭제는 shift 비용

LinkedList
  - 노드 객체 연결
  - index 접근 O(n)
  - 포인터 추적과 cache miss
  - 노드 참조를 이미 알 때 연결 변경 O(1)
```

---

## 진단 포인트

- 실제 연산 비율이 조회/순회/삽입/삭제 중 어디에 몰리는지 본다.
- 위치를 이미 알고 있는 삽입인지, 위치 탐색부터 필요한 삽입인지 구분한다.
- 객체 수와 GC 압력을 확인한다.
- 데이터 크기가 CPU cache 효과가 드러날 만큼 큰지 확인한다.

---

## 트레이드오프

배열 기반 구조는 이동 비용을 치르는 대신 접근과 순회가 빠르다. 노드 기반 구조는 연결 변경은 싸지만 탐색과 메모리 접근 비용이 크다.
