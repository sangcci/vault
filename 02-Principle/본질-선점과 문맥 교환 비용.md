# Principle: 선점과 문맥 교환 비용

**핵심 질문**: OS가 공정하게 CPU를 나눠줄수록 왜 비용이 생기는가?

## 한 문장 정의

선점과 문맥 교환 비용은 OS가 실행 중인 작업을 강제로 멈추고 다른 작업으로 전환해 공정성과 반응성을 얻는 대신, 상태 저장·복원과 캐시/TLB 손실 비용을 지불한다는 원리.

---

## 해결하는 문제

- 스레드를 많이 만들었는데 context switch만 증가하는 문제
- time quantum이 너무 작아 실제 업무보다 전환 비용이 커지는 문제
- lock을 잡은 thread가 선점되어 대기 확산이 생기는 문제
- 선점형 OS 스케줄링과 협력형 이벤트 루프의 차이를 이해하는 문제

---

## 판단 기준

```text
선점이 필요한 이유
  - CPU 독점 방지
  - 시스템 반응성 유지
  - 우선순위 작업 처리

문맥 교환 비용
  - register/PC/SP 저장·복원
  - kernel stack 전환
  - address space/TLB 영향
  - cache locality 손실
```

---

## 진단 포인트

- voluntary context switch와 involuntary context switch를 구분한다.
- lock wait, blocking I/O, sleep이 voluntary switch를 늘리는지 본다.
- timer preemption과 runnable 경쟁이 involuntary switch를 늘리는지 본다.
- context switch 증가가 latency와 cache miss 증가로 이어지는지 확인한다.

---

## 트레이드오프

선점이 없으면 하나의 작업이 CPU를 독점할 수 있다. 선점이 많으면 공정성은 높아지지만 전환 비용이 커진다. 좋은 스케줄링은 CPU를 공정하게 나누면서도 실제 작업보다 전환 비용이 커지지 않게 균형을 잡는 것이다.
