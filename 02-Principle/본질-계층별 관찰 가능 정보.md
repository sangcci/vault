# Principle: 계층별 관찰 가능 정보

**핵심 질문**: 왜 어떤 장비는 IP와 Port만 보고, 어떤 장비는 Host와 Path까지 볼 수 있는가?

## 한 문장 정의

계층별 관찰 가능 정보는 네트워크 장비나 소프트웨어가 자신이 처리하는 계층의 헤더와 상태만 기준으로 판단할 수 있으며, 상위 계층 의미는 그 계층을 해석하는 주체만 볼 수 있다는 원리.

---

## 해결하는 문제

- 같은 IP의 여러 도메인을 L4 설정만으로 분기하려다 실패하는 문제
- NAT, 방화벽, L4 LB, L7 reverse proxy의 역할을 혼동하는 문제
- Host header 기반 virtual hosting을 IP 기반 라우팅과 같은 것으로 보는 문제
- Cloudflare/ALB/Nginx/iptables의 책임 경계를 구분하지 못하는 문제

---

## 판단 기준

```text
L3
  - IP 주소
  - routing

L4
  - TCP/UDP
  - port
  - connection tuple

L7
  - HTTP Host
  - path
  - method
  - header/cookie
  - 일부 body
```

분기 기준이 어느 계층 정보인지 먼저 본다.

```text
IP 차단 / 포트 포워딩 / DNAT
  → L3/L4

Host 기반 라우팅 / path 기반 라우팅 / WAF / 인증
  → L7
```

---

## 트레이드오프

낮은 계층은 빠르고 범용적이지만 애플리케이션 의미를 모른다. 높은 계층은 의미 기반 제어가 가능하지만 프로토콜 해석, TLS 종료, proxy 운영 비용이 생긴다. 좋은 네트워크 설계는 한 도구로 모든 것을 하려 하지 않고 계층별 책임을 나눈다.
