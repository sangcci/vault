# Principle: 물리 주소와 논리 식별자의 분리

**핵심 질문**: 빠르게 찾아가기 위한 물리 위치를 왜 row의 정체성으로 쓰면 안 되는가?

## 한 문장 정의

물리 주소와 논리 식별자의 분리는 DB 내부의 page/slot/ctid 같은 위치 정보는 빠른 접근을 위한 임시 주소이고, 외부에서 row를 안정적으로 식별하려면 primary key 같은 논리 식별자를 사용해야 한다는 원리.

---

## 해결하는 문제

- PostgreSQL `ctid`를 안정적인 row id로 사용하는 문제
- 인덱스가 사용하는 TID와 애플리케이션 식별자를 혼동하는 문제
- UPDATE/VACUUM 후 물리 위치가 바뀌는 이유를 이해하지 못하는 문제
- 논리 row와 row version을 구분하지 못하는 문제

---

## 판단 기준

```text
물리 주소
  - page id + slot/item pointer
  - tuple version 위치
  - 빠른 접근 가능
  - 이동/재작성/업데이트에 따라 바뀔 수 있음

논리 식별자
  - primary key
  - business identity 또는 surrogate id
  - 외부 참조에 안정적
  - row 의미를 식별
```

---

## 진단 포인트

- 외부 API, 캐시 key, 다른 테이블 FK에 ctid/물리 위치를 쓰는지 확인한다.
- UPDATE 후 row version이 새로 만들어지는 DB인지 확인한다.
- 내부 최적화용 단발 쿼리와 장기 식별자를 구분한다.
- primary key가 없는 테이블이 있는지 확인한다.

---

## 트레이드오프

물리 주소는 빠르지만 안정성이 없다. 논리 키는 한 번 더 찾아가는 비용이 있지만 의미와 참조 안정성을 제공한다. DB는 내부에서 물리 주소를 쓰고, 외부 계약에는 논리 키를 노출한다.
