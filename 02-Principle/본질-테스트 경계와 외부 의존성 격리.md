# Principle: 테스트 경계와 외부 의존성 격리

**핵심 질문**: 이 테스트가 실패했을 때 내 코드가 문제인지 외부 시스템이 문제인지 구분할 수 있는가?

## 한 문장 정의

테스트 경계와 외부 의존성 격리는 애플리케이션 테스트에서 외부 API의 상태, 속도, 장애를 테스트 범위 밖으로 밀어내고 요청/응답 계약만 통제된 stub으로 검증해야 한다는 원리.

---

## 판단 기준

```text
Unit / slice test
  - 외부 API 호출 금지
  - mock/stub 사용

Integration test
  - DB/Testcontainers 등 필요한 의존성만 실제화
  - 외부 HTTP는 WireMock 등으로 통제

E2E / contract test
  - 실제 외부 시스템 검증
  - 적은 수로 분리 실행
```

---

## 실무 기준

- 테스트 endpoint는 운영 endpoint와 물리적으로 다르게 둔다.
- test profile에서 외부 API 주소를 명시적으로 override한다.
- timeout/5xx/invalid body 같은 실패 응답도 stub으로 고정한다.
- 실제 외부 호출 테스트는 느린 테스트 그룹으로 분리한다.
- 테스트 시작 시 운영 URL이 주입되면 실패시킨다.
