# Principle: 집계 단위와 함수 종속

**핵심 질문**: GROUP BY 이후 어떤 컬럼은 왜 SELECT할 수 있고 어떤 컬럼은 왜 오류가 나는가?

## 한 문장 정의

집계 단위와 함수 종속은 GROUP BY가 결과 row의 원자 단위를 정하고, SELECT의 비집계 컬럼은 그 단위 안에서 하나의 값으로 결정되어야 한다는 원리.

---

## 해결하는 문제

- GROUP BY 후 비집계 컬럼 조회 시 42803 오류가 발생하는 문제
- MySQL에서 되던 집계 쿼리가 PostgreSQL에서 깨지는 문제
- 집계 결과와 상세 컬럼을 한 row에 함께 담을 때 그룹 단위를 잘못 잡는 문제
- QueryDSL/ORM의 Java 재조합과 SQL GROUP BY를 혼동하는 문제

---

## 판단 기준

SELECT에 있는 표현식은 다음 중 하나여야 한다.

```text
1. GROUP BY key
2. aggregate function 결과
3. GROUP BY key로 하나의 값이 결정되는 컬럼
```

함수 종속은 이렇게 읽는다.

```text
survey.id가 primary key
  ↓
survey.id → survey.title
  ↓
GROUP BY survey.id가 있으면 title은 그룹 안에서 하나로 결정
```

---

## 진단 포인트

- 지금 GROUP BY가 어떤 단위의 결과 row를 만드는지 먼저 정한다.
- SELECT의 비집계 컬럼이 그 단위 안에서 하나로 결정되는지 확인한다.
- PK/UNIQUE NOT NULL 같은 DB 제약이 실제 존재하는지 확인한다.
- “어차피 같은 값일 것”이라는 애플리케이션 가정만으로는 SQL 결정성이 보장되지 않는다.
- 상세 row와 집계 row를 동시에 원하면 window function이나 2단계 조합을 검토한다.

---

## 트레이드오프

GROUP BY를 넓게 잡으면 오류는 사라지지만 결과 row 단위가 바뀔 수 있다. GROUP BY를 좁게 잡으면 원하는 집계 단위는 유지되지만, 비집계 컬럼을 꺼내려면 함수 종속이나 별도 조합이 필요하다.

## 참고

> "When GROUP BY is present, or any aggregate functions are present, it is not valid for the SELECT list expressions to refer to ungrouped columns except within aggregate functions or when the ungrouped column is functionally dependent on the grouped columns" — [PostgreSQL Documentation: SELECT](https://www.postgresql.org/docs/current/sql-select.html)

> "A functional dependency exists if the grouped columns (or a subset thereof) are the primary key of the table containing the ungrouped column." — [PostgreSQL Documentation: SELECT](https://www.postgresql.org/docs/current/sql-select.html)
