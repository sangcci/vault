# Principle: 논리 모델과 조회 비용의 균형

**핵심 질문**: 정규화된 좋은 모델이 언제 조회 비용을 키우는가?

## 한 문장 정의

논리 모델과 조회 비용의 균형은 데이터 무결성을 위해 사실을 나누어 저장하면 쓰기 정합성은 좋아지지만, 읽을 때 JOIN과 재조합 비용이 생기므로 workload에 따라 정규화와 비정규화 경계를 조절해야 한다는 원리.

---

## 해결하는 문제

- 정규화는 항상 좋고 비정규화는 항상 나쁘다고 보는 문제
- 조회 성능 때문에 중복 저장하면서 원본과 동기화 책임을 정하지 않는 문제
- OLTP와 OLAP/대시보드 모델을 같은 기준으로 설계하는 문제
- 키 설계와 인덱스 순서를 논리 모델과 분리해서 생각하는 문제

---

## 판단 기준

```text
정규화에 유리한 상황
  - 쓰기/수정이 많음
  - 데이터 정합성이 중요
  - 같은 사실이 여러 곳에 반복되면 위험
  - OLTP core table

비정규화 고려 상황
  - 읽기 비중이 높음
  - JOIN 비용이 병목
  - snapshot/reporting 용도
  - 원본과 갱신 정책이 명확
```

---

## 진단 포인트

- 이 테이블이 source of truth인지 cache/read model인지 구분한다.
- 중복 컬럼이 어떤 원본에서 파생되는지 확인한다.
- 갱신 빈도와 조회 빈도를 비교한다.
- JOIN 비용이 실제 병목인지 실행 계획으로 확인한다.
- 비정규화 데이터의 재계산/보정 전략이 있는지 본다.

---

## 트레이드오프

정규화는 변경 안전성을 높이고 저장 중복을 줄인다. 비정규화는 읽기를 단순하게 만들지만 중복 정합성 비용을 애플리케이션이나 배치 작업으로 이동시킨다.
