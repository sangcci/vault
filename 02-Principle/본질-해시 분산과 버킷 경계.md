# Principle: 해시 분산과 버킷 경계

**핵심 질문**: HashMap의 O(1)은 어떤 조건이 깨지면 무너지는가?

## 한 문장 정의

해시 분산과 버킷 경계는 해시 기반 자료구조의 평균 O(1) 성능이 key가 bucket에 고르게 분산되고 capacity/load factor 경계가 적절히 관리된다는 전제에 의존한다는 원리.

---

## 해결하는 문제

- HashMap 조회를 조건 없는 O(1)로 믿는 문제
- 잘못된 `hashCode()`/`equals()`로 충돌과 누락이 생기는 문제
- resize/rehash 시점의 latency spike를 놓치는 문제
- capacity를 너무 작게 또는 너무 크게 잡아 성능을 망치는 문제

---

## 판단 기준

```text
HashMap 성능 조건
  - hashCode가 key를 고르게 분산
  - equals와 hashCode 계약 일치
  - capacity와 load factor 적절
  - key가 불변 또는 map에 들어간 뒤 hash 기준이 변하지 않음

비용 발생 지점
  - bucket collision
  - treeification
  - resize/rehash
  - capacity + size에 비례하는 iteration
```

---

## 진단 포인트

- custom key의 `hashCode()`와 `equals()`를 확인한다.
- key 분포가 특정 bucket에 몰리는지 본다.
- 대량 삽입 전에 initial capacity를 설정했는지 확인한다.
- iteration이 중요하면 capacity가 과도하게 큰지 확인한다.
- 순서/범위 조회가 필요하면 HashMap이 맞는지 다시 판단한다.

---

## 트레이드오프

HashMap은 평균 조회가 빠르지만 순서와 범위 질의를 포기한다. 분산이 나쁘면 bucket 내부 탐색 비용이 커지고, load factor 경계에서는 resize 비용을 치른다.
