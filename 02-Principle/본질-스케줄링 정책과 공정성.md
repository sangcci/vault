# Principle: 스케줄링 정책과 공정성

**핵심 질문**: 다음에 실행할 작업을 고르는 기준은 무엇을 최적화하는가?

## 한 문장 정의

스케줄링 정책과 공정성은 한정된 실행 자원을 여러 작업에 배분할 때 응답 시간, 처리량, 우선순위, 기아 방지 중 무엇을 우선할지 정하는 원리.

---

## 해결하는 문제

- CPU 스케줄링 정책을 잘못 잡아 짧은 요청이 긴 작업 뒤에서 밀리는 문제
- FCFS, SJF, SRT, RR, Priority, HRN을 이름만 외우고 선택 기준을 놓치는 문제
- interactive 요청과 batch 작업을 같은 큐에서 처리해 tail latency가 나빠지는 문제
- 공정성과 처리량, context switch 비용의 균형을 잡지 못하는 문제

---

## 판단 기준

```text
FCFS
  - 도착 순서
  - 단순하지만 convoy effect

SJF / SRT
  - 짧은 작업 우선
  - 평균 대기 시간 유리
  - 작업 시간 예측과 starvation 문제

Round Robin
  - time quantum 순환
  - 응답성/공정성 유리
  - quantum이 작으면 context switch 폭증

Priority
  - 중요 작업 우선
  - aging 없으면 starvation

CFS
  - vruntime으로 덜 실행된 task를 우선
  - 범용 OS의 공정성 근사
```

---

## 진단 포인트

- 최적화 목표가 평균 대기 시간인지 p99 latency인지 처리량인지 정한다.
- 작업 길이 분포가 긴 꼬리를 가지는지 본다.
- starvation이 허용되지 않는 작업이 있는지 확인한다.
- interactive/batch/real-time 작업을 같은 큐에 넣어도 되는지 검토한다.
- time quantum 또는 worker batch size가 context switch와 latency에 미치는 영향을 본다.

---

## 트레이드오프

공정하게 나누면 모두가 기회를 얻지만 전환 비용이 생긴다. 짧은 작업을 우선하면 평균 응답은 좋아지지만 긴 작업이 밀릴 수 있다. 우선순위를 두면 중요한 작업은 빨라지지만 낮은 우선순위 작업에 aging이 필요하다.
