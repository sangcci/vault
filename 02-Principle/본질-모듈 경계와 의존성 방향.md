# Principle: 모듈 경계와 의존성 방향

**핵심 질문**: 이 경계는 어떤 변경과 의존성을 막기 위해 존재하는가?

## 한 문장 정의

모듈 경계와 의존성 방향은 시스템을 단순히 폴더나 빌드 단위로 나누는 것이 아니라, 변경 이유가 다른 코드가 서로 직접 의존하지 않도록 경계와 참조 방향을 강제하는 원리.

---

## 판단 기준

```text
모듈로 나눌 이유
  - 변경 주기가 다름
  - 실행/배포 단위가 다름
  - 기술 구현체를 숨겨야 함
  - 팀/업무 경계가 다름
  - 의존성 방향을 강제해야 함

나누지 말아야 할 이유
  - 멋있어 보여서
  - DDD처럼 보여서
  - 폴더가 많으면 구조적이라고 느껴져서
```

---

## 실무 기준

- 작은 CRUD는 먼저 단순한 layered 구조로 시작한다.
- core는 usecase, domain rule, port를 담당한다.
- support/infra는 DB, Redis, 외부 API 구현체를 담당한다.
- api/batch/scheduler는 실행 진입점과 protocol adapter를 담당한다.
- common 모듈이 모든 것을 아는 우회로가 되지 않게 한다.
