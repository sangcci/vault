# Principle: 관측 데이터 최소화와 민감정보 경계

**핵심 질문**: 이 로그는 장애 분석에 필요한 신호인가, 아니면 원본 데이터의 위험한 복사본인가?

## 한 문장 정의

관측 데이터 최소화와 민감정보 경계는 로그·메트릭·트레이스에 문제 분석에 필요한 최소 신호만 남기고 개인정보와 시크릿 같은 원본 값은 저장하지 않는 원리.

---

## 판단 기준

```text
남길 것
  - query skeleton
  - latency
  - row count
  - error code
  - trace id
  - actor id hash/masked

남기지 말 것
  - password
  - token / secret
  - 주민번호 / 카드번호
  - 원문 payload 전체
  - 불필요한 개인 식별값
```

---

## 실무 기준

- 운영 로그는 디버깅 편의보다 유출 위험을 먼저 본다.
- 값이 필요하면 마스킹, 해시, 샘플링을 적용한다.
- 로그 저장소 접근 권한은 애플리케이션보다 넓어지기 쉬우므로 별도 통제한다.
- 관측 목적별로 로그, 메트릭, 트레이스를 분리한다.
- 민감정보가 한 번 로그에 들어가면 삭제와 전파 통제가 어렵다.
