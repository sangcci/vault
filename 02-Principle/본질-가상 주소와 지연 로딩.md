# Principle: 가상 주소와 지연 로딩

**핵심 질문**: 메모리에 있는 것처럼 보이는 데이터는 실제로 언제 물리 메모리에 올라오는가?

## 한 문장 정의

가상 주소와 지연 로딩은 프로세스가 연속된 가상 주소 공간을 보는 동안, 실제 물리 페이지와 파일 데이터는 접근 시점의 page fault와 커널 paging 정책에 의해 뒤늦게 연결된다는 원리.

---

## 해결하는 문제

- `mmap()`을 파일 전체를 즉시 메모리에 올리는 API로 오해하는 문제
- page fault 지연이 애플리케이션 latency에 섞여 들어오는 문제
- 논리 주소의 연속성과 물리 메모리/디스크 접근 비용을 혼동하는 문제
- 커널 page cache와 애플리케이션 buffer pool의 제어권 차이를 판단하는 문제

---

## 판단 기준

```text
mmap(file)
  - virtual address range 생성
  - file offset과 주소 범위 연결
  - 즉시 전체 데이터 read 아님

first access
  - page table entry 없음
  - page fault
  - kernel이 file page를 RAM/page cache에 로드
  - page table 갱신 후 재시작
```

---

## 진단 포인트

- major/minor page fault를 구분한다.
- 접근 패턴이 순차인지 랜덤인지 본다.
- working set이 RAM보다 큰지 확인한다.
- latency spike가 page fault, readahead, eviction과 관련되는지 본다.
- I/O scheduling을 커널에 맡겨도 되는 workload인지 판단한다.

---

## 트레이드오프

가상 주소와 지연 로딩은 큰 파일을 단순한 메모리 접근처럼 다루게 해준다. 하지만 실제 I/O 비용은 접근 시점으로 밀려나며, 커널의 paging·eviction 정책에 의존하게 된다.
