# Principle: 신뢰 체인과 키 소유권 증명

**핵심 질문**: 처음 만난 공개키가 정말 그 주체의 키인지 어떻게 믿는가?

## 한 문장 정의

신뢰 체인과 키 소유권 증명은 공개키 자체가 아니라, 신뢰된 제3자가 서명한 인증서와 root trust anchor까지 이어지는 검증 경로로 공개키의 소유자를 확인한다는 원리.

---

## 해결하는 문제

- 공개키만 보고 상대방 신원을 확인할 수 없는 문제
- TLS를 써도 공격자가 공개키를 바꿔치기할 수 있는 문제
- self-signed 인증서를 무조건 신뢰하는 문제
- 인증서 만료/폐기/hostname 검증을 무시하는 문제

---

## 판단 기준

```text
검증해야 할 것
  - certificate chain이 trusted root까지 이어지는가
  - CA signature가 유효한가
  - hostname/SAN이 요청 도메인과 일치하는가
  - validity 기간이 유효한가
  - revocation/정책 조건이 맞는가
```

---

## 진단 포인트

- TLS verification을 끄는 코드가 있는지 확인한다.
- trust store에 어떤 root CA를 신뢰하는지 본다.
- 내부 사설 CA의 private key 관리와 rotation 절차가 있는지 본다.
- 인증서 갱신 자동화와 만료 알림을 확인한다.

---

## 트레이드오프

PKI는 인터넷 규모에서 낯선 주체의 키를 검증하게 해준다. 대신 CA와 trust store에 신뢰를 위임하므로, CA 침해나 잘못된 예외 허용은 전체 신뢰를 무너뜨릴 수 있다.
