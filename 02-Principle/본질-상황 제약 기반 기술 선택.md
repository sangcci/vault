# Principle: 상황 제약 기반 기술 선택

**핵심 질문**: 이 선택은 지금 서비스 규모와 팀 역량에서 감당 가능한가?

## 한 문장 정의

상황 제약 기반 기술 선택은 기술의 일반적 장단점보다 유저 규모, 데이터 규모, 변경 빈도, 팀 규모, 운영 역량 같은 현재 제약 안에서 얻는 것과 포기하는 것을 비교해 선택하는 원리.

---

## 판단 기준

```text
상황 입력
  - 유저 규모
  - 데이터 규모
  - 성장 추세
  - 요구사항 변경 빈도
  - 팀 규모
  - 운영/DevOps 역량

선택 출력
  - 얻는 것
  - 포기하는 것
  - 지금 감당 가능한 복잡도
```

---

## 실무 기준

- 정답 기술보다 현재 제약을 먼저 말한다.
- 복잡한 구조는 팀이 운영할 수 있을 때만 선택한다.
- 트레이드오프는 단점이 아니라 선택의 근거다.
- 면접/문서에서는 상황 → 기준 → 선택 → 트레이드오프 순서로 설명한다.
- 채용공고도 기술 목록보다 회사의 제약과 문제를 읽는다.
