# Principle: 인터페이스 의미와 도메인 언어

**핵심 질문**: 이 이름과 경로는 사용자가 무엇을 식별하고 무엇을 조건으로 거는지 드러내는가?

## 한 문장 정의

인터페이스 의미와 도메인 언어는 API 경로, 파라미터, DTO, 매핑 테이블 이름이 기술적 편의가 아니라 자원 식별 방식과 팀의 도메인 관점을 드러내야 한다는 원리.

---

## 판단 기준

```text
Path Variable
  - 단건 자원 식별
  - /reservations/{id}

Query Parameter
  - 목록 검색/필터/정렬/페이징
  - /reservations?status=PENDING&page=0

Name
  - 중심 도메인 개념
  - 팀이 실제로 부르는 말
```

---

## 실무 기준

- endpoint는 프론트 URL 미감보다 API 계약 의미를 우선한다.
- 변환 객체 이름은 Mapper/Converter/Formatter 책임을 섞지 않는다.
- 매핑 테이블 이름은 관계의 중심 개념을 드러낸다.
- 이름만 보고 변경 이유와 소유 책임을 추론할 수 있어야 한다.
