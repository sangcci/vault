# Principle: 폭발 반경과 격벽

**핵심 질문**: 장애가 났을 때 어디까지 죽게 내버려 둘 것인가?

## 한 문장 정의

폭발 반경과 격벽은 장애·침해·자원 폭주가 전체 시스템으로 번지지 않도록 VM, 네트워크, 도메인, 환경 경계를 나누는 원리.

---

## 해결하는 문제

- 한 서비스의 장애가 같은 host나 같은 네트워크의 다른 서비스까지 전파되는 문제
- 개발/스테이징 실수가 운영 데이터에 영향을 주는 문제
- Web/WAS/DB를 왜 목적별로 분리하는지 설명하기 어려운 문제
- 비용 절감을 위해 모든 것을 한 곳에 모았다가 장애 범위가 커지는 문제

---

## 깨지는 상황

```text
모든 워크로드를 같은 경계에 배치
  ↓
배치 작업 I/O 폭주
  ↓
DB latency 증가
  ↓
WAS timeout 증가
  ↓
전체 서비스 장애로 확대
```

격벽이 없으면 장애는 가장 약한 연결을 따라 번진다. 격벽은 장애를 없애는 장치가 아니라 장애가 퍼지는 경로를 제한하는 장치다.

---

## 판단 기준

- 보안 신뢰도가 다른 시스템은 같은 경계에 두지 않는다.
- stateful DB와 stateless WAS는 장애 특성과 복구 방식이 다르므로 경계를 나눈다.
- dev/stage/prod는 데이터와 권한을 분리해 실수가 운영으로 번지지 않게 한다.
- 비용이 허용하는 범위에서 서비스, 도메인, tenant, 가용 영역 단위로 격벽을 둔다.
- 격리 단위를 늘릴수록 운영 복잡도와 관측 비용이 증가함을 함께 고려한다.

---

## 트레이드오프

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| 큰 공유 경계 | 비용 절감, 운영 단순 | 장애 전파 범위 증가 |
| VM/네트워크 분리 | 장애·보안 경계 명확 | 비용과 관리 포인트 증가 |
| 도메인별 분리 | 비즈니스 장애 격리 | 데이터 동기화/통합 복잡도 |
| 환경별 분리 | 운영 데이터 보호 | 환경 차이 관리 필요 |
| Cell 구조 | 장애 범위 극소화 | 인프라 중복과 라우팅 복잡도 |
