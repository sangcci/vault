# Principle: 페이지 단위 저장과 간접 참조

**핵심 질문**: DB는 가변 길이 row를 고정 크기 page 안에서 어떻게 안정적으로 찾는가?

## 한 문장 정의

페이지 단위 저장과 간접 참조는 DB가 table과 index를 고정 크기 page 배열로 저장하고, page 내부에서는 slot/item pointer가 tuple의 실제 위치를 가리켜 tuple 이동과 외부 참조를 분리한다는 원리.

---

## 해결하는 문제

- row가 page 내부에서 이동하면 인덱스 참조가 모두 깨진다고 오해하는 문제
- DB page, heap page, index page, OS page를 구분하지 못하는 문제
- TID/ctid가 왜 page 번호와 slot 번호 조합인지 이해하지 못하는 문제
- page bloat, dead tuple, vacuum을 물리 구조와 연결하지 못하는 문제

---

## 판단 기준

```text
Table / Index
  - fixed-size page 배열

Page 내부
  - PageHeader
  - ItemId / Slot array
  - Free space
  - Tuple / Index item

간접 참조
  external reference: (page id, slot number)
  slot: tuple offset/length
  tuple 이동: slot만 갱신
```

---

## 진단 포인트

- 성능 문제가 몇 row가 아니라 몇 page를 읽는 문제인지 본다.
- index가 heap page 접근을 얼마나 줄이는지 확인한다.
- dead tuple과 bloat로 실제 읽는 page가 늘었는지 확인한다.
- 논리 정렬 순서와 물리 저장 순서가 같은지 따로 확인한다.

---

## 트레이드오프

페이지와 slot 간접 참조는 tuple 이동과 가변 길이 저장을 가능하게 한다. 대신 page header/slot overhead와 fragmentation 관리, vacuum 같은 유지보수 비용이 생긴다.
