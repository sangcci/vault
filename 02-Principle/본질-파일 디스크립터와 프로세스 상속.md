# Principle: 파일 디스크립터와 프로세스 상속

**핵심 질문**: Unix는 어떻게 부모가 만든 입출력 연결을 자식 프로세스에게 넘기는가?

## 한 문장 정의

파일 디스크립터와 프로세스 상속은 Unix 프로세스가 `fork()`로 부모의 열린 파일 디스크립터와 실행 문맥을 상속받고, `execve()`로 프로그램 이미지만 교체하면서도 입출력 연결은 유지할 수 있다는 원리.

---

## 해결하는 문제

- 쉘 파이프라인이 서로 다른 프로그램의 stdin/stdout을 연결하는 문제
- `fork`와 `execve`가 왜 분리되어 있는지 이해하는 문제
- `dup2`, `close`를 잘못 써서 EOF가 전달되지 않거나 파이프가 멈추는 문제
- 부모의 환경 변수, 권한, 열린 파일을 자식에게 전달하는 구조를 이해하는 문제

---

## 판단 기준

```text
pipe(fd)
  fd[0] = read end
  fd[1] = write end

fork()
  parent의 fd table 복제
  child도 같은 pipe endpoint를 가리킴

dup2(fd[1], STDOUT_FILENO)
  child stdout을 pipe write end로 교체

execve("grep", ...)
  process image 교체
  fd 연결은 유지
```

---

## 진단 포인트

- 자식이 필요 없는 fd를 닫았는지 확인한다.
- 부모도 pipe의 사용하지 않는 쪽을 닫았는지 확인한다.
- `execve` 성공 후 원래 코드가 실행되지 않는다는 점을 고려한다.
- fork 후 exec 전 구간에서 멀티스레드 lock 상태를 조심한다.
- `FD_CLOEXEC`가 필요한 fd와 유지되어야 하는 fd를 구분한다.

---

## 트레이드오프

fork/exec 구조는 부모가 준비한 환경과 입출력 연결을 자식에게 자연스럽게 상속시키지만, 파일 디스크립터 생명주기를 잘못 관리하면 EOF 누락, 자원 누수, 예기치 않은 권한/연결 상속이 생긴다.
