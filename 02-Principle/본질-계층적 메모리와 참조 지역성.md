# Principle: 계층적 메모리와 참조 지역성

**핵심 질문**: 왜 가까운 데이터를 연속해서 읽는 코드가 더 빠른가?

## 한 문장 정의

계층적 메모리와 참조 지역성은 CPU cache, RAM, disk처럼 속도와 용량이 다른 계층에서 최근 접근한 데이터와 인접한 데이터가 다시 사용될 가능성을 활용해 성능을 얻는 원리.

---

## 해결하는 문제

- 같은 시간복잡도인데 실제 성능이 크게 다른 이유를 설명하지 못하는 문제
- ArrayList 순회가 LinkedList 순회보다 빠른 이유를 Big-O만으로 설명하지 못하는 문제
- cache, OS page cache, DB buffer pool, application cache를 별개 암기 대상으로만 보는 문제
- 랜덤 접근과 순차 접근의 비용 차이를 놓치는 문제

---

## 판단 기준

```text
시간 지역성 Temporal locality
  - 방금 쓴 데이터는 곧 다시 쓸 가능성이 높음

공간 지역성 Spatial locality
  - 방금 쓴 주소 근처의 데이터도 곧 쓸 가능성이 높음

계층적 메모리
  register < L1/L2/L3 cache < RAM < SSD < Network
  빠른 계층일수록 작고 비쌈
```

---

## 진단 포인트

- 자료구조가 연속 메모리인지 포인터 기반인지 확인한다.
- 순차 접근인지 랜덤 접근인지 구분한다.
- working set이 cache/RAM에 들어가는지 본다.
- 캐시 적중률이 낮아질 만큼 key space가 넓은지 확인한다.
- 성능 문제가 CPU 연산인지 메모리 대기인지 프로파일링한다.

---

## 트레이드오프

참조 지역성을 살리면 같은 연산 수라도 훨씬 빠르게 실행될 수 있다. 하지만 접근 패턴이 랜덤하거나 working set이 계층 용량을 넘으면 캐시는 효과를 잃고 오히려 관리 비용만 남는다.
