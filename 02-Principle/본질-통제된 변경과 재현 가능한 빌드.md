# Principle: 통제된 변경과 재현 가능한 빌드

**핵심 질문**: 같은 commit을 내일 빌드해도 같은 결과가 나오는가?

## 한 문장 정의

통제된 변경과 재현 가능한 빌드는 운영 시스템에 들어오는 dependency, 설정, 빌드 결과의 변화를 사람이 검토하고 고정해 예측하지 못한 변경이 장애로 들어오지 않게 하는 원리.

---

## 판단 기준

```text
위험한 변경
  - floating version
  - 자동 minor/major update
  - changelog 미확인
  - rollback 계획 없음

통제된 변경
  - version pinning
  - changelog 확인
  - 영향 범위 테스트
  - staged rollout
  - rollback 계획
```

---

## 실무 기준

- 운영 서비스 dependency는 명시적으로 고정한다.
- 메이저 버전은 초기 패치가 나온 뒤 검토한다.
- 보안 패치는 빠르게 적용하되 회귀 테스트를 준비한다.
- 빌드 산출물, 설정, 마이그레이션 이력을 함께 추적한다.
- 수치 목표와 근거를 남겨 변경 후 영향을 비교한다.
