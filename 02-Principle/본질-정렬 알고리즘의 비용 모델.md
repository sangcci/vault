# Principle: 정렬 알고리즘의 비용 모델

**핵심 질문**: 단순 정렬 알고리즘은 어떤 입력에서 비용이 달라지는가?

## 한 문장 정의

정렬 알고리즘의 비용 모델은 비교, 교환, 이동, 입력의 기존 정렬 정도, 추가 메모리 사용 여부에 따라 같은 O(n²) 정렬도 실제 성능과 적합성이 달라진다는 원리.

---

## 해결하는 문제

- Bubble/Insertion/Selection sort를 이름과 코드만 외우는 문제
- 거의 정렬된 데이터에서 삽입 정렬이 유리한 이유를 모르는 문제
- 선택 정렬이 항상 전체 탐색을 해야 하는 이유를 놓치는 문제
- 정렬 알고리즘을 시간복잡도 하나로만 비교하는 문제

---

## 판단 기준

```text
Bubble Sort
  - 인접 원소 교환 반복
  - 교환이 많음
  - 조기 종료 가능하면 이미 정렬된 입력 O(n)

Insertion Sort
  - 왼쪽 정렬 구간에 삽입
  - 거의 정렬된 입력에 강함
  - 작은 배열에서 실용적

Selection Sort
  - 남은 구간 최솟값 선택
  - 교환 횟수는 적음
  - 이미 정렬되어도 비교 O(n²)
```

---

## 진단 포인트

- 입력 크기가 작은지 큰지 확인한다.
- 입력이 거의 정렬되어 있는지 본다.
- 비교 비용과 교환/이동 비용 중 무엇이 큰지 본다.
- 안정 정렬이 필요한지 확인한다.
- 실무에서는 라이브러리 정렬을 우선 사용하되, 알고리즘 문제에서는 조건을 분리한다.

---

## 트레이드오프

단순 정렬은 이해와 구현은 쉽지만 큰 입력에서는 비효율적이다. 다만 작은 입력이나 거의 정렬된 입력처럼 조건이 맞으면 복잡한 정렬보다 단순한 알고리즘이 충분히 빠를 수 있다.
