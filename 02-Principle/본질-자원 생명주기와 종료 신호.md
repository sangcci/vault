# Principle: 자원 생명주기와 종료 신호

**핵심 질문**: 이 자원은 누가 열고, 누가 닫으며, 닫힘이 누구에게 어떤 신호를 주는가?

## 한 문장 정의

자원 생명주기와 종료 신호는 파일, 소켓, 파이프, DB connection 같은 외부 자원은 유한하므로 사용 후 명시적으로 닫아 반납·flush·EOF 같은 종료 신호를 전달해야 한다는 원리.

---

## 판단 기준

```text
open / borrow
  - file descriptor
  - socket
  - stream
  - DB connection

use
  - read/write/query

close / return
  - FD 반납
  - EOF 전달
  - buffer flush
  - pool 반환
```

---

## 실무 기준

- Java는 try-with-resources를 기본으로 사용한다.
- 예외 경로에서도 close가 실행되는지 확인한다.
- connection pool은 connection을 닫는 것이 실제 TCP 종료가 아니라 pool 반환일 수 있다.
- 파이프/소켓은 닫지 않으면 상대가 EOF를 못 받아 대기할 수 있다.
- 자원 누수는 장애 전까지 조용히 누적된다.
