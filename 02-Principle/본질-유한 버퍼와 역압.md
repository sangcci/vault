# Principle: 유한 버퍼와 역압

**핵심 질문**: 소비자가 생산자보다 느릴 때 시스템은 어떻게 무한 메모리 증가를 막는가?

## 한 문장 정의

유한 버퍼와 역압은 생산 속도가 소비 속도를 초과할 때 제한된 버퍼가 가득 차면 생산자를 대기·실패·감속시켜 전체 시스템의 메모리 폭주를 막는 원리.

---

## 해결하는 문제

- 파이프라인에서 downstream이 느려져 upstream이 멈춘 것처럼 보이는 문제
- 큐와 버퍼를 무한히 늘리면 안정성이 좋아진다고 착각하는 문제
- TCP flow control, OS pipe, reactive streams, bounded queue를 별개 개념으로만 보는 문제
- 처리량 병목과 backpressure를 장애로 오해하는 문제

---

## 판단 기준

```text
Producer rate > Consumer rate
  → buffer fill
  → capacity reached
  → one of:
       block producer
       fail/write EAGAIN
       drop data
       slow down via protocol signal
```

파이프의 경우:

```text
pipe buffer full
  → blocking fd: write() waits
  → non-blocking fd: write() fails with EAGAIN
```

---

## 진단 포인트

- buffer 크기가 유한한지, 무한 증가 가능한지 확인한다.
- full 상태에서 block/fail/drop 중 어떤 정책인지 확인한다.
- upstream이 멈춘 원인이 downstream 지연인지 확인한다.
- backpressure가 전파되지 않아 중간 queue만 커지는지 본다.
- latency 증가와 memory 증가를 함께 본다.

---

## 트레이드오프

역압은 처리량을 순간적으로 낮추지만 시스템 붕괴를 막는다. 반대로 역압이 없으면 생산자는 계속 밀어 넣고, 중간 버퍼가 메모리를 잠식하거나 데이터가 무제한 지연된다.
