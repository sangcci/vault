# Principle: 부분 순서와 전체 순서의 차이

**핵심 질문**: 가장 작은 값 하나를 빨리 찾는 것과 전체 순서를 유지하는 것은 왜 다른 문제인가?

## 한 문장 정의

부분 순서와 전체 순서의 차이는 heap처럼 최우선 원소만 빠르게 찾기 위한 구조와 BST처럼 모든 원소 간 정렬 관계를 유지하는 구조가 제공하는 연산과 비용이 다르다는 원리.

---

## 해결하는 문제

- PriorityQueue로 range query나 정렬 순회를 하려는 문제
- TreeMap을 단순 min/max 추출 용도로만 써서 비용을 과하게 지불하는 문제
- Heap을 정렬된 트리로 오해하는 문제
- 자료구조의 보장 범위를 API 이름만 보고 판단하는 문제

---

## 판단 기준

```text
Heap / PriorityQueue
  - root만 최소/최대 보장
  - poll O(log n)
  - peek O(1)
  - 임의 탐색/범위 조회 약함

BST / TreeMap
  - 전체 key order 유지
  - get/put/remove O(log n)
  - floor/ceiling/range/ordered iteration 가능
```

---

## 진단 포인트

- 필요한 연산이 최우선 원소 반복 추출인지 확인한다.
- 정렬 순회, 범위 조회, predecessor/successor가 필요한지 확인한다.
- 원소 갱신/삭제를 임의 위치에서 해야 하는지 본다.
- 자료구조가 제공하지 않는 연산을 우회 구현하고 있지 않은지 본다.

---

## 트레이드오프

부분 순서 구조는 유지해야 할 정보가 적어 특정 연산이 빠르다. 전체 순서 구조는 더 많은 관계를 유지하므로 다양한 순서 연산을 제공하지만 더 많은 비용을 치른다.
