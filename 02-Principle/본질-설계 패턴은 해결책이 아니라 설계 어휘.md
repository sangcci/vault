# Principle: 설계 패턴은 해결책이 아니라 설계 어휘

**핵심 질문**: 이 패턴 이름이 실제 문제를 설명하는가, 아니면 설계를 끌고 가는가?

## 한 문장 정의

설계 패턴은 반복되는 설계 문제와 구조에 붙인 공통 어휘일 뿐이며, 패턴 이름을 먼저 적용하는 것이 아니라 변경 가능성·중복·책임 분리 문제가 드러났을 때 설명과 소통에 사용해야 한다는 원리.

---

## 판단 기준

```text
좋은 사용
  문제 발견 -> 구조 선택 -> 패턴 이름으로 설명

나쁜 사용
  패턴 이름 선택 -> 코드 구조 강제 -> 문제는 나중에 끼워 맞춤
```

---

## 실무 기준

- 패턴은 코드 리딩 속도를 높이는 어휘다.
- 패턴은 팀 설계 소통을 압축하는 이름이다.
- 기술 전체를 단일 패턴으로 정의하지 않는다.
- 숨길 복잡성이나 변경 가능성이 없으면 패턴을 추가하지 않는다.
- 면접 답변도 “무슨 패턴”보다 “무슨 문제와 비용”을 먼저 말한다.
