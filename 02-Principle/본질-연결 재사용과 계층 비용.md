# Principle: 연결 재사용과 계층 비용

**핵심 질문**: 왜 같은 데이터를 보내도 연결을 새로 만들면 느려지는가?

## 한 문장 정의

연결 재사용과 계층 비용은 애플리케이션 요청 하나가 하위 계층의 연결 생성, 순서 보장, ACK, 흐름 제어 비용 위에서 실행되므로, 반복 요청은 연결과 전송 상태를 재사용해야 지연을 줄일 수 있다는 원리.

---

## 해결하는 문제

- 요청마다 새 TCP 연결을 만들어 응답 지연과 연결 비용이 커지는 문제
- Stop-and-Wait처럼 ACK마다 멈추면 회선 이용률이 낮아지는 문제
- Sliding Window, ARQ, Keep-Alive를 서로 별개 용어로만 외우는 문제
- HTTP 성능 문제를 애플리케이션 코드만 보고 판단하는 문제

---

## 판단 기준

```text
하위 계층 비용
  - TCP handshake
  - TLS handshake
  - sequence/ACK 관리
  - congestion window warm-up
  - retransmission
  - receive window / flow control

반복 요청
  → persistent connection / connection pool / multiplexing 검토

긴 RTT
  → handshake 반복 비용이 더 크게 보임
```

---

## 신뢰성과 처리량의 관계

```text
Stop-and-Wait
  send 1개 → ACK 대기 → 다음 전송
  → 단순하지만 RTT 낭비 큼

Sliding Window
  window 크기만큼 연속 전송
  ACK 수신 시 window 이동
  → 회선 이용률 증가

SACK / Selective Repeat
  받은 구간을 알려줌
  빠진 segment만 재전송
  → 불필요한 재전송 감소
```

---

## 트레이드오프

연결을 재사용하면 latency와 CPU 비용은 줄지만, 유휴 연결이 socket과 memory를 점유한다. window를 키우면 처리량은 늘지만, 손실이나 혼잡 시 버퍼와 재전송 비용이 커질 수 있다.
