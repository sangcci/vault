# Principle: 동시성 제어와 격리

**핵심 질문**: 동시에 실행되는 작업들이 서로의 중간 상태를 얼마나 보게 할 것인가, 그리고 충돌을 어떤 방식으로 조정할 것인가?

## 한 문장 정의

동시성 제어와 격리는 **여러 트랜잭션이 같은 데이터를 동시에 읽고 쓸 때 허용할 간섭 수준을 정하고, 충돌을 대기·실패·재시도·직렬화 중 어떤 방식으로 처리할지 결정하는 원리**다.

---

## 해결하는 문제

동시성 제어는 다음 문제를 다룬다.

```text
- 같은 재고를 동시에 차감해 수량이 틀어짐
- 같은 예약 좌석을 동시에 배정함
- 같은 주문 상태를 서로 다른 상태로 전이함
- 중복 생성 방어를 SELECT 후 INSERT로만 처리해 race condition 발생
- lock 대기가 길어져 latency와 connection 점유가 증가함
```

핵심은 모든 문제를 같은 방식으로 막을 수 없다는 점이다.

```text
단순 카운터 증감 → Atomic UPDATE
읽은 값 기반 판단 → Lock 또는 Optimistic Version
여러 조건의 일관된 snapshot 필요 → Isolation level / Serializable / 재시도
중복 생성 방어 → Unique Constraint / Idempotency Key
```

---

## 깨지는 상황

격리 수준을 높이면 모든 동시성 문제가 자동으로 사라진다고 생각할 때 깨진다. 반대로 기본 격리 수준에서 어떤 이상 현상이 가능한지 모르면 운영 중에만 문제가 드러난다.

```text
낮은 격리:
  처리량은 좋지만 일부 이상 현상 가능

높은 격리:
  일관성은 강하지만 재시도, 대기, 성능 비용 증가
```

Read Committed에서는 두 SELECT가 같은 트랜잭션 안에 있어도 다른 결과를 볼 수 있다.

```text
T1: SELECT count → 10
T2: UPDATE count = 11 COMMIT
T1: SELECT count → 11
```

Repeatable Read나 Serializable은 더 강한 보장을 주지만, 충돌 시 트랜잭션 재시도가 필요할 수 있다.

```text
ERROR: could not serialize access due to concurrent update
→ 현재 트랜잭션 abort
→ 처음부터 다시 실행
```

## 판단 기준

문제의 형태를 먼저 분류한다.

```text
1. 단일 row의 단순 증감인가?
   → Atomic UPDATE

2. 같은 row를 읽고 복잡한 업무 판단을 하는가?
   → Optimistic Lock 또는 SELECT FOR UPDATE

3. 충돌이 드문가?
   → Optimistic Lock + retry

4. 충돌이 잦고 재시도 비용이 큰가?
   → Pessimistic Lock + lock timeout + 짧은 transaction

5. 여러 row/table을 읽고 invariant를 지켜야 하는가?
   → Serializable 또는 명시적 lock/constraint/state model 재설계
```

선택 흐름:

```text
동시성 문제 발견
      ↓
상태 변경을 한 SQL로 표현 가능?
      ├─ YES → Atomic UPDATE
      │
      └─ NO
          ↓
     충돌 시 재시도 가능?
          ├─ YES → Optimistic Lock
          └─ NO  → Pessimistic Lock / Queue / Serializable 검토
```

운영 기준도 같이 본다.

```text
- lock wait time
- deadlock count
- serialization failure count
- retry success rate
- connection pool active/idle/pending
- p95/p99 latency
```

## 트레이드오프

```text
Read Committed
  장점: 빠르고 기본값이라 운영 비용 낮음
  단점: 복잡한 조회-판단-갱신에는 부족할 수 있음

Optimistic Lock
  장점: lock 점유 없이 충돌 감지
  단점: 충돌이 많으면 재시도 폭증

Pessimistic Lock
  장점: 판단 구간을 직접 보호
  단점: 대기, deadlock, connection 점유

Serializable
  장점: 가장 강한 격리 의미
  단점: serialization failure 재시도와 모니터링 필요
```

중요한 결론:

```text
동시성 제어는 정답 하나를 고르는 문제가 아니다.
문제의 형태, 충돌 빈도, 재시도 가능성, 사용자가 감당할 실패 UX를 같이 보고 선택한다.
```
