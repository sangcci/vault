# Principle: 작업 공간 격리와 컨텍스트 전환 비용

**핵심 질문**: 지금 작업 중인 맥락을 버리지 않고 다른 브랜치 작업을 할 수 있는가?

## 한 문장 정의

작업 공간 격리와 컨텍스트 전환 비용은 서로 다른 브랜치 작업을 하나의 working directory에서 계속 전환하면 stash, 충돌, 상태 혼선 비용이 생기므로 독립 작업 공간으로 분리할 수 있다는 원리.

---

## 판단 기준

```text
하나의 working directory
  feature 작업 중
    ↓ hotfix 발생
  stash / checkout / pop
    ↓
  충돌 또는 맥락 손실

분리된 worktree
  project-feature/
  project-hotfix/
    ↓
  각 브랜치 상태 독립 유지
```

---

## 실무 기준

- 긴급 hotfix는 stash보다 별도 worktree를 고려한다.
- 장기 feature와 release 검증을 동시에 해야 할 때 worktree가 유리하다.
- 각 worktree의 브랜치/경로/IDE 창을 명확히 구분한다.
- 완료된 worktree는 제거해 작업 공간을 정리한다.
