# Principle: 의사결정 증거로서의 문서화

**핵심 질문**: 이 문서는 무엇을 만들었는가보다 왜 그렇게 만들었는가를 증명하는가?

## 한 문장 정의

의사결정 증거로서의 문서화는 프로젝트 문서가 기능 목록을 설명하는 데 그치지 않고 문제 상황, 선택 기준, 대안, 결과 수치, 트레이드오프를 남겨 기술 판단의 깊이를 증명해야 한다는 원리.

---

## 판단 기준

```text
기능 나열 문서
  - 무엇을 만들었는가
  - 어떤 기술을 썼는가

의사결정 문서
  - 어떤 문제가 있었는가
  - 어떤 기준으로 골랐는가
  - 대안은 무엇이었는가
  - 결과는 어떻게 바뀌었는가
  - 무엇을 포기했는가
```

---

## 실무 기준

- 성능 개선은 Before/After 수치로 쓴다.
- 장애 대응은 현상 → 원인 추론 → 해결 → 재발 방지로 쓴다.
- API/ERD/아키텍처 그림에는 선택 이유를 붙인다.
- 포트폴리오는 기술 스택보다 문제 해결 흐름을 앞에 둔다.
- SI/인수인계 문서는 검수와 유지보수의 증거라는 점을 고려한다.
