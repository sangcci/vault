# 레거시 리팩토링 하면서 느낀점

- auth 리팩토링 당시 레거시 코드들이 너무 많았고 그에 따라 업무를 이해하기 굉장히 힘들었음
- 다른 도메인의 경계를 넘나들었고, 스파게티처럼 의존성이 엮임 -> 이 로직이 왜 필요한지 모름
- AI에게 업무를 전담해야 했고, AI도 우리 프로젝트 업무를 다 아는 것은 아니기 때문에 날마다 구현 방식이 달라짐

처음에 회귀 테스트를 고정하고 시작했다. 하지만 정확히 어떤 테스트를 작성하는지까진 모르고, AI에게 맡겼다. 그리고 AI와 함께 usecase 별로 나눠서 하나씩 리팩토링을 시작했다.
먼저 각 usecase마다 업무 흐름을 먼저 AI와 함께 파악하고, 정책 검증 로직인지, 데이터 반영하는 작업인지 등을 파악하고 한개씩 변경했다.
원래 내 생각으로는 코드 일부분을 고치면 될줄 알았지만, 막상 클래스 전체를 뒤바꾸는 작업을 하고 있었다.
하면 할수록 기존 코드랑 더 섞여서 나의 인지 능력을 벗어났다.

업무 성격을 미리 파악하자. 정책이 많을 것 같은지, 조회 위주인지, 외부 API와 많이 엮어있는지 등을 파악하는것이 시작.
이것이 소프트웨어의 설계 방향을 결정한다.
