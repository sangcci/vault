# API 이름은 통일된 용어 기반으로 만들자

## API 이름
AI가 지어준 대로 구분하면 
- 홈 성수 컨텐츠 조회
- 지도 기반 장소 조회
- 선택 장소 주변 게시글 마커 조회

이런식으로 사람이 읽고 이해할 수 없다.

화면을 보고 API를 설계하는 것이 맞지만, 화면이 바텀시트에 있건 어떤걸 클릭해서 나오는거던 다 상관없이, 

데이터, 컴포넌트 화면 만을 보고 입출력을 생각해서 API 설계해야한다.

그렇게 하면 위 예시를 다음과 같이 바꿀 수 있다.
- 장소 목록 조회
- 지도 범위 내 장소 목록 조회
- 장소 단일 요약 조회
- 장소 주변 분실물 및 습득물 목록 조회

우리가 조회하고자 하는 데이터의 영역 및 도메인 용어가 통일되어야 한다. - 장소, 성수 컨텐츠 혼용 X

바텀시트에서 조회하건, 리스트에서 조회하던 간에 조회하는 데이터가 일치하는지 여부가 중요하다. - 홈 성수 컨텐츠 조회는 홈 영역, 바텀시트 둘 다 사용됨

해당 데이터를 부를 때 어떤 입력 값을 사용하는지를 주의깊게 살펴보자. - placeId로만 조회한다면 굳이 장소 동네 정보 조회라고 하지 않아도 되지 않을까?
