# Github Issue는 완벽히 관리될 필요가 없다

작업 내용 밑에 상세 내용이 항상 템플릿에 있다.
상세 내용은 왜있는걸까? 
어차피 상세 내용은 작업하면서 계속 바뀌게 되어있는데.

Issue를 보는 시점은
- 팀원들과 같이 스프린트할 때
- 지난 작업 단위를 보고 싶을 때
이제는 AI에게 시키면 지난 작업 단위를 모두 분석해서 우리에게 알려준다. 

- **작업의 단위가 겹치지 않게** 하거나
- **팀원의 일정을 알게 하고**
- **작업 상태를 공유하는 공간**에 더 가깝다

"내가 이 작업을 수행하겠다", "이런 버그가 발생했더라", "이 부분에 대해서 논의하고 싶다" 라는 메세지를 팀원들에게 전달하는거지.

그 이외에 ADR 처럼 지난 작업의 결정을 보는 것은 잘못되었다. 위에서 상세 내용과 동일한 맥락으로, 어차피 PR 올릴 때 바뀌거든.

Issue 자체를 꾸미려고 하면 안된다. 순서가 잘못되었다.
Issue를 쓰는 이유를 알면 자연스레 정렬이 되고 꾸며지게 되있다.

> Issue를 작성할 때 이런 쓰임을 계속 인지하고 있는게 중요하다.
