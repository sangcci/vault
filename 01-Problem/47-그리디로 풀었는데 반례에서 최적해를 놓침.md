# Problem: 47-그리디로 풀었는데 반례에서 최적해를 놓침

## 상황

매 순간 가장 좋아 보이는 선택을 하면 전체도 최적일 것 같아서 그리디로 풀었다. 예제는 맞았지만, 반례에서 더 나은 선택을 놓친다.

```text
현재 가장 가까워지는 이동 선택
  → 당장은 좋아 보임
  → 미래 선택지를 망쳐 전체 최적 실패
```

---

## 관찰된 증거

- 예제는 맞지만 숨은 테스트에서 틀린다.
- 현재 선택을 바꿨을 때 미래 선택지가 크게 달라진다.
- “항상 ~가 제일 좋아 보인다”는 감으로 증명 없이 선택한다.
- DP로는 풀리지만 그리디 조건을 증명하지 못한다.
- 반례 하나를 만들 수 있다.

---

## 의심 문제

가장 가능성 높은 문제는 **그리디 선택 속성을 증명하지 않고 지역 최적을 전역 최적으로 가정한 것**이다.

그리디는 빠르지만 모든 최적화 문제에 맞지 않는다. 현재 선택이 최적해 일부로 교환 가능하다는 증명이 필요하다.

---

## 원인

```text
그리디가 맞으려면:
  1. Greedy choice property
     현재 지역 최적 선택이 어떤 전역 최적해에도 포함될 수 있음

  2. Optimal substructure
     선택 후 남은 문제의 최적해와 결합해 전체 최적해 구성 가능

증명 실패:
  현재 선택이 미래 선택지를 망침
  → 상태 기억 필요
  → DP/BFS/완전탐색 후보
```

---

## 확인 방법

- 선택 기준을 명확한 비교 함수로 표현한다.
- exchange argument로 내 선택을 최적해의 선택과 바꿔도 손해가 없는지 증명한다.
- 작은 입력에서 brute force로 반례를 찾는다.
- 선택 후 이전 상태를 완전히 잊어도 되는지 확인한다.
- 상태를 기억해야 하면 DP 또는 그래프 탐색으로 전환한다.

---

## 해결책 후보

| 조건 | 선택 |
|---|---|
| exchange argument로 정당화 가능 | Greedy |
| 선택 후 상태 조합 최적화 필요 | DP |
| 최소 이동 횟수/상태 공간 | BFS |
| 비용 누적 최단 경로 | Dijkstra 등 |
| 입력 작음 | Brute force로 검증/반례 탐색 |

---

## 트레이드오프

그리디는 상태를 많이 기억하지 않아 빠르고 단순하다. 하지만 그 단순함은 문제 구조가 현재 선택을 안전하게 만들어줄 때만 성립한다. 증명 없는 그리디는 최적화가 아니라 추측이다.
