# Problem: 66-컨테이너 PID 1이 자식 프로세스를 수거하지 않아 좀비가 쌓임

## 상황

컨테이너에서 애플리케이션이 shell script나 worker process를 자식으로 띄운다. 부모가 종료된 자식 프로세스를 `wait()`하지 않거나, PID 1 역할을 하는 프로세스가 signal 전달과 child reaping을 제대로 처리하지 않아 zombie process가 쌓인다.

```text
container PID 1 = app or shell
  ├─ worker A exits
  ├─ worker B exits
  └─ parent does not wait()
       ↓
    zombie entries remain
```

---

## 관찰된 증거

- `ps`에서 `Z` 상태 프로세스가 보인다.
- 컨테이너 종료 시그널이 애플리케이션에 제대로 전달되지 않는다.
- worker를 많이 띄우는 배치/크롤러/영상 처리 작업에서 시간이 지날수록 이상해진다.
- 로컬 실행과 Docker 실행의 종료 동작이 다르다.
- shell form ENTRYPOINT가 signal을 삼킨다.

---

## 원인

Unix 계열에서 종료된 child는 parent가 `wait()`로 종료 상태를 회수해야 완전히 정리된다. 일반 OS에서는 init/systemd가 orphan을 입양하고 수거하지만, 컨테이너 안에서는 PID 1이 곧 애플리케이션일 수 있다. 이 프로세스가 init 역할을 하지 않으면 signal 처리와 child reaping 문제가 생긴다.

---

## 해결 방향

- Docker `--init` 또는 tini/dumb-init 같은 경량 init을 사용한다.
- ENTRYPOINT는 가능하면 exec form을 사용해 signal 전달을 명확히 한다.
- 애플리케이션이 자식 프로세스를 만들면 SIGCHLD와 wait 처리를 확인한다.
- Kubernetes에서는 terminationGracePeriod와 preStop hook이 실제 프로세스에 닿는지 확인한다.
- 단순 웹 서버는 자식 프로세스 생성 여부를 줄이고, worker는 별도 supervisor를 둔다.
