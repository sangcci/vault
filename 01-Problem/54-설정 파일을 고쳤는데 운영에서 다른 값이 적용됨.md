# Problem: 54-설정 파일을 고쳤는데 운영에서 다른 값이 적용됨

## 상황

`application-prod.yml` 값을 수정하고 재배포했는데 운영 동작이 바뀌지 않는다. 실제 런타임에서는 환경 변수나 command line 인자가 더 높은 우선순위로 값을 덮어쓰고 있었다.

```text
application.yml        db.pool=10
application-prod.yml   db.pool=20
ENV DB_POOL            db.pool=50  ← 최종 적용
```

---

## 관찰된 증거

- 파일에는 원하는 값이 있는데 런타임 값은 다르다.
- 로컬과 운영에서 같은 profile인데 값이 다르게 나온다.
- 설정 출처를 로그로 남기지 않아 어디서 덮였는지 모른다.
- secret 값 확인을 위해 운영 로그에 평문을 찍으려 한다.

---

## 원인

외부 설정은 여러 source를 계층으로 쌓고, 우선순위가 높은 source가 낮은 source를 덮어쓴다. 이 구조는 편하지만, 설정 출처가 보이지 않으면 디버깅이 어려워진다.

---

## 해결 방향

- 핵심 설정은 기동 시 **값이 아니라 출처(origin)** 를 로그로 남긴다.
- `password`, `token`, `secret`, `key`는 평문 로그 금지.
- 필수 설정은 없거나 범위를 벗어나면 fail-fast로 기동 실패시킨다.
- 설정 계층은 `default → profile → env` 정도로 단순화한다.
- 운영에서 덮어쓰는 값은 배포 문서/런북에 명시한다.
