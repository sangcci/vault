# Problem: 70-자원 종료와 의존성 버전 관리를 미뤄 운영 장애가 발생함

## 상황

파일, 소켓, DB connection, 외부 프로세스 같은 자원을 열고 닫지 않거나, 패키지 버전을 자동 업데이트에 맡긴다. 개발 환경에서는 잘 동작하지만 운영에서는 FD 고갈, connection pool 고갈, 예상치 못한 breaking change로 장애가 난다.

```text
request
  -> open file/socket/db connection
  -> exception occurs
  -> close skipped
  -> resource leak accumulates
```

---

## 관찰된 증거

- 시간이 지날수록 연결 수나 FD 수가 증가한다.
- 파이프/소켓의 쓰기 쪽이 닫히지 않아 읽는 쪽이 EOF를 받지 못한다.
- 오늘 빌드와 내일 빌드가 다른 dependency를 사용한다.
- minor/patch 자동 업데이트 후 테스트는 통과했지만 운영 특정 경로가 깨진다.
- 성능·가용성 수치 목표가 없어서 장애 기준도 애매하다.

---

## 원인

운영 시스템은 우연히 동작하면 안 된다. 자원은 생명주기를 닫아야 하고, 의존성 변경은 통제되어야 하며, 비기능 목표는 수치와 근거로 관리되어야 한다.

---

## 해결 방향

- 파일/소켓/stream/connection은 try-with-resources, defer, finally 등으로 닫는다.
- close는 메모리 절약뿐 아니라 EOF/flush/반납 신호라는 점을 이해한다.
- dependency version은 고정하고, 변경은 changelog·테스트·롤백 계획과 함께 진행한다.
- 보안 패치는 예외적으로 빠르게 적용하되 영향 범위를 검증한다.
- 성능·가용성·보안 목표는 수치와 출처를 남긴다.
