# Problem: 16-같은 클래스 내부 호출로 트랜잭션이나 캐시가 적용되지 않음

## 상황

서비스 메서드 안에서 같은 클래스의 다른 메서드를 호출한다. 호출된 메서드에는 `@Transactional`, `@Cacheable`, `@Async` 같은 Spring AOP 기반 어노테이션이 붙어 있다.

```java
@Service
public class OrderService {
    public void placeOrder() {
        validate();
        saveInNewTransaction(); // 내부 호출
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void saveInNewTransaction() {
        orderRepository.save(order);
    }
}
```

코드만 보면 새 트랜잭션이 열릴 것 같지만, 실제로는 어노테이션이 적용되지 않는다.

---

## 관찰된 증거

- `REQUIRES_NEW`가 붙었는데 새 트랜잭션이 시작되지 않는다.
- `@Cacheable`이 붙은 메서드를 내부 호출하면 캐시 hit/miss 로그가 없다.
- `@Async`가 붙은 내부 메서드가 별도 thread에서 실행되지 않는다.
- 외부 Bean에서 같은 메서드를 호출하면 정상 동작한다.

```text
외부 호출
Client → Proxy → Target.method()  ✅ Advice 적용

내부 호출
Target.outer() → this.inner()     ❌ Proxy 우회
```

---

## 의심 문제

가장 가능성 높은 문제는 **Spring AOP 프록시를 거치지 않는 self-invocation**이다.

Spring AOP는 target 객체 자체를 바꾸는 것이 아니라, target 앞에 proxy를 세워 외부 호출을 가로챈다. 같은 객체 내부의 `this.method()` 호출은 proxy를 지나지 않는다.

---

## 원인

AOP 어노테이션은 메서드에 붙어 있지만, 실제 부가 기능은 프록시가 호출을 가로챌 때 실행된다.

```text
Bean 등록 시
Target 객체
  ↑
Proxy 객체가 감쌈

외부에서 Bean 호출
caller → proxy → advice(begin/cache/async) → target

내부 this 호출
target.outer → target.inner
              ↑ proxy 없음
```

따라서 self-invocation 문제는 단순히 `@Transactional` 하나의 문제가 아니라, Spring proxy 기반 cross-cutting concern 전체의 문제다.

---

## 확인 방법

- 문제가 되는 메서드가 같은 클래스 안에서 `this.method()` 또는 암묵적 내부 호출로 실행되는지 본다.
- 호출 경로가 Spring Bean proxy를 통과하는지 확인한다.
- 로그로 transaction begin/commit, cache hit/miss, async thread 이름을 비교한다.
- `AopUtils.isAopProxy(bean)`와 실제 호출 대상 분리를 확인한다.
- 단위 테스트가 아니라 Spring context 기반 통합 테스트로 재현한다.

---

## 해결책 후보

| 해결책 | 장점 | 비용/위험 |
|---|---|---|
| Bean 분리 | 가장 명확하고 순환 참조 위험 낮음 | 클래스 수 증가 |
| Application Service에서 usecase 분리 | 호출 흐름과 트랜잭션 경계가 명확해짐 | 설계 리팩터링 필요 |
| 자기 자신 proxy 주입 | 빠른 우회 가능 | 순환 참조, 가독성 저하 |
| TransactionTemplate 사용 | proxy 의존 없이 명시적 경계 제어 | 선언형보다 코드 증가 |
| AspectJ weaving | self-invocation까지 처리 가능 | 설정 복잡도 증가 |

---

## 트레이드오프

프록시 기반 AOP는 단순하고 Spring Bean 모델과 잘 맞지만, 호출이 프록시를 통과해야 한다는 제약이 있다. 내부 호출이 필요한 구조라면 “어노테이션을 어디에 붙일까”보다 “usecase 경계와 Bean 경계를 어떻게 나눌까”를 먼저 봐야 한다.
