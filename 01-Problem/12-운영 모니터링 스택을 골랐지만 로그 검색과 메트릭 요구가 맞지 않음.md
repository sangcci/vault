# Problem: 12-운영 모니터링 스택을 골랐지만 로그 검색과 메트릭 요구가 맞지 않음

## 상황

운영 모니터링을 위해 Prometheus, Grafana, Loki 또는 ELK를 검토한다. 그런데 “로그도 보고 메트릭도 보고 대시보드도 필요하다”는 말만으로 도구를 고르면 실제 요구와 맞지 않을 수 있다.

```text
요구 A: p99 latency, error rate, CPU, memory 알람
요구 B: 특정 사용자 로그 전문 검색
요구 C: 장기 보관과 비용 절감
요구 D: 한 화면에서 metrics + logs 연결
```

이 요구들은 모두 옵저버빌리티처럼 보이지만, 저장하는 데이터 모델과 인덱싱 비용이 다르다.

---

## 관찰된 증거

- Prometheus에 로그 본문 검색을 기대한다.
- Loki를 도입했는데 Elasticsearch 같은 자유로운 전문 검색을 기대한다.
- Grafana를 설치했지만 뒤에 붙은 데이터 소스 품질이 낮아 대시보드가 의미 없다.
- 단일 Prometheus로 장기 보관, 전역 집계, 멀티테넌시까지 해결하려 한다.
- ELK를 도입했지만 실제로는 단순 운영 로그 보관과 장애 시 원인 확인 정도만 필요하다.

```text
도구 이름 중심 선택
  ↓
데이터 성격 불일치
  ↓
검색 성능 / 저장 비용 / 운영 복잡도 불만
```

---

## 의심 문제

가장 가능성 높은 문제는 **관측 데이터의 성격을 구분하지 않고 도구를 고른 것**이다.

도구 선택은 제품 비교가 아니라 “어떤 신호를 어떤 방식으로 저장하고, 어떤 비용으로 조회할 것인가”의 문제다.

---

## 원인

Metrics, logs, traces는 모두 운영 신호지만 저장·조회 방식이 다르다.

```text
Metrics
  숫자 시계열 / label / 구간 집계 / alert
  → Prometheus, Mimir, VictoriaMetrics, Datadog

Logs
  이벤트 본문 / label 또는 full-text index / 원인 확인
  → Loki, ELK

View
  여러 데이터 소스 시각화 / dashboard / alert 화면
  → Grafana, Kibana
```

Prometheus는 숫자 시계열에 강하고, Loki는 label 중심 로그 조회와 비용 효율에 강하다. ELK는 로그 본문과 필드를 강하게 색인해 검색 자유도를 높이는 대신 비용과 운영 복잡도가 커진다. Grafana는 저장소가 아니라 여러 데이터 소스를 연결해 보여주는 표현 계층이다.

---

## 확인 방법

- 주 요구가 “수치 알람”인지 “로그 전문 검색”인지 “분석용 이벤트 검색”인지 분리한다.
- 로그 조회가 label 기반 후보 축소로 충분한지, 본문/필드 전문 검색이 필요한지 확인한다.
- metrics 보관 기간, 전역 집계, 멀티테넌시 요구를 확인한다.
- Grafana 같은 view 계층과 Prometheus/Loki/Elastic 같은 storage/query 계층을 분리해 본다.
- 운영 인력, 저장 비용, 장애 대응 runbook까지 포함해 비교한다.

---

## 해결책 후보

| 해결책 | 장점 | 비용/위험 |
|---|---|---|
| Prometheus + Grafana + Loki | 운영 모니터링, 비용 효율, metrics/logs 연결에 적합 | 로그 전문 검색은 약함 |
| ELK | 본문 검색, 필드 분석, 보안/감사 로그 분석에 강함 | 색인 비용과 운영 복잡도 큼 |
| Prometheus + ELK 혼합 | metrics와 로그 분석 요구를 각각 최적화 | 운영 구성 증가 |
| Prometheus + Mimir/VictoriaMetrics | 장기 보관/확장 보강 | 추가 backend 운영 필요 |
| Datadog 같은 SaaS | 운영 부담 감소, 통합 경험 | 비용과 벤더 종속성 |

---

## 트레이드오프

싸고 단순한 로그 저장소는 검색 자유도를 일부 포기한다. 반대로 강한 검색 플랫폼은 색인 비용과 운영 복잡도를 감수한다.

따라서 “어떤 도구가 더 좋은가”보다 “우리 장애 대응에서 가장 자주 던지는 질문이 무엇인가”를 먼저 정해야 한다.
